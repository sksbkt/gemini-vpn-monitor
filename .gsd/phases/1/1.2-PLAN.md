# Plan 1.2: Dynamic Poller Reconfiguration in Main Process

## Objective
Refactor the background ping loop in `main.js` to dynamically consume the loaded/updated configuration (`pingTarget`, `pingIntervalMs`, `pingTimeoutMs`) at runtime, clear ping history smoothly when the target changes, and ensure the UI status payload transmits the active target and metrics without app restarts.

## Context
- .gsd/SPEC.md
- .gsd/ROADMAP.md
- .gsd/phases/1/1.1-PLAN.md
- main.js
- preload.js

## Tasks

<task type="auto">
  <name>Refactor ping execution and monitoring loop to use dynamic settings</name>
  <files>main.js</files>
  <action>
    In `main.js`:
    1. Update `runPing()` to accept `(target, timeoutMs)` dynamically from `currentSettings.pingTarget` and `currentSettings.pingTimeoutMs`.
    2. In `startMonitoring()`, replace hardcoded `1000` interval with `currentSettings.pingIntervalMs`. Calculate `waitTime = Math.max(50, currentSettings.pingIntervalMs - elapsed)`.
    3. Update the dispatched status payload: `server: currentSettings.pingTarget`.
    4. In `settings:save` IPC handler (from Plan 1.1):
       - Detect if `pingTarget` changed. If changed, reset `history = []` to avoid mixing ping metrics from different servers.
       - Ensure `currentSettings` is immediately updated in memory so the very next loop iteration uses the new target and interval without restarting the loop.
  </action>
  <verify>node -e "const main = require('fs').readFileSync('main.js', 'utf8'); if (main.includes('currentSettings.pingTarget') && main.includes('currentSettings.pingIntervalMs')) console.log('DYNAMIC_SETTINGS_FOUND'); else process.exit(1);"</verify>
  <done>`main.js` references `currentSettings` dynamically in ping execution and loop delays instead of hardcoded constants.</done>
</task>
